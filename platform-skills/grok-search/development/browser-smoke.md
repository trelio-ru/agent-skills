# Браузерная проверка Grok

## Scope и release review

Новый instruction-only provider `grok-search`, версия первого выпуска `1.0.0`.
Source baseline — `1ed2e18ccc3a93b870b6acaf57f7fa0537bcc7b6` в
`trelio-ru/agent-skills`; предыдущего Grok tag/package нет. Candidate — exact
commit/PR с этим документом. Публикация фиксирует его SHA, PR и фактические
результаты описанной ниже проверки в release summary, а не в mutable Git pointer.

Транспорт — существующий browser tool, без нового host ABI, account namespace,
credential store, executable или runtime package. Навык самостоятельно ведёт
публичное исследование/обсуждение в рамках поручения. Дополнительное согласование
на каждый запуск, запрос и уточнение в инструкцию не добавляется. Отдельные
разрешения browser tool и доступ к закрытым данным сохраняются.

Из-за добавления exact source route, hosted test и эквивалентного fallback
меняется общая CI-инфраструктура. Проверки selector-а обязаны сохранить полный
набор прежних native OS gates и дополнить source gate Grok. Сам Grok не входит
в runtime-package OS matrix. Full cold/fault backend stand не требуется: общие
runtime/admission/ACL/encrypted-delivery контракты не меняются.

## Preflight 5 ноября 2026 года

В собственной скрытой IAB-вкладке проверены главная grok.com, composer,
«Отправить» и меню режима. Гостю показан «Быстрый»; «Авто», «Эксперт», «Тяжёлый»
помечены «Требуется вход». Подписи не закреплены как постоянный API.

После одного публичного технического вопроса появился блок пользователя,
но вместо ответа — «Продолжить разговор» и предложение регистрации. Это
доказательство ограничения гостевого доступа, не успешного диалога и не пустой
выдачи. Открыта штатная страница входа для ручной авторизации; auth-поля, tokens,
профиль/cookies и чужая история не читались. Вопрос не отправлялся повторно.

## Обязательный live цикл перед публикацией

1. После ручного входа проверить рабочую собственную беседу по UI. Не считать
   наличие composer доказательством ответа. При утрате гостевого вопроса начать
   самостоятельный новый запрос, обозначив новую сессию, без поиска в истории.
2. Вставить controller из SKILL.md напрямую в REPL. Один публичный вопрос:
   действующий RFC для HTTP/2, номер, дата и ссылка на официальный первоисточник.
   Проверить принятый вопрос, полный новый ответ и завершение генерации по
   штатным response actions. Счётчик поиска/мышление не заменяют completion.
3. Во второй ход той же беседы спросить, какой документ был заменён этим RFC,
   либо попросить сравнить факты из первого ответа. Сохранить вкладку/controller,
   проверить второй вопрос и соответствующий завершённый ответ. Не менять чат
   ради уточнения и не согласовывать его с пользователем.
4. Прочитать настоящие href цитат/панели источников. Открыть нужный официальный
   документ в своей скрытой вспомогательной вкладке и проверить точный факт,
   дату и применимость. Не сохранять промежуточные рассуждения Grok и не
   объявлять недоступный источник проверенным.
5. Проверить выбранный режим по текущему UI. Отдельно записать, какие режимы
   удалось проверить; одна видимая подпись не доказывает live доступность всех.
6. После публикации сверить current version, карточку, routingSummary, keywords,
   SHA-256 полной канонической инструкции и отсутствие runtime/Remote MCP.
   Повторить безопасный browser-сценарий по опубликованной инструкции.

Каждый вопрос отправляется один раз через общий controller. После готового
ответа выдерживается только остаток интервала 2–15 секунд, с зачётом времени
чтения/размышлений. Неизвестная отправка сначала reconciled в исходной беседе;
новый чат/режим/вход не дают replay authority. В конце закрываются только свои
вкладки, без удаления истории.

Public evidence содержит только безопасные вопросы, проверенные публичные
источники и результаты. Account, auth DOM/screenshots, внутренние URL/IDs чатов,
tracking/session-параметры и личная история в source/fixtures не входят.
