# Восстановление ввода и выбор другого навыка

Контракт относится к instruction-only контроллерам Google, Яндекса, Perplexity,
DeepSeek и GigaChat. Provider сохраняет browser tool, одну беседу, completion clock
и отдельную границу отправки. Host ABI, аккаунты, cookies, права и платные режимы
не меняются; executable package и новый minimum host не нужны.

## Исполняемые сценарии

Каждый provider test загружает свой фактический snippet из SKILL.md, без второй
копии контроллера. Добавлены четыре проверки:

- Ошибка non-submitting `prepare` не вызывает `sendOnce`; другой способ ввода
  продолжает тот же controller без ручного сброса
- Повтор подготовки сохраняет исходный completion deadline и не выбирает новую
  случайную паузу. После 7 из 15 секунд ожидаются только оставшиеся 8
- Незавершённый `prepare` удерживает единственный submission slot; параллельная
  отправка запрещена и после отказа освобождается только этот слот
- Успешная подготовка с ошибкой `sendOnce` остаётся unknown. Следующая попытка
  не выполняет ни ввод, ни отправку; старый combined callback также остаётся fenced

Общие source/instruction tests проверяют все 25 инструкций, UTF-8 byte guard и
text-compatible envelope. Эти assertions не доказывают поведение живой модели.

## Живая проверка Google, 7 ноября 2026

В собственной скрытой IAB-вкладке открыта обычная выдача по публичной теме
`HTTP cache control MDN`. Наблюдённый combobox «Найти» вернул
`Accessibility element 10 has no settable value` внутри `prepare`.
Счётчик вызовов отправки остался равен нулю; поле сохранило старый вопрос.

После свежего DOM snapshot тот же controller использовал документированный
`getByRole("combobox", {name:"Найти", exact:true}).fill(...)` в `prepare`,
а один `.press("Enter")` — в `sendOnce`. Счётчик стал равен единице.
Новая выдача содержала именно `site:developer.mozilla.org Cache-Control no-cache`
и ссылки MDN. Только после просмотра готовой новой выдачи вызван `answerReady()`.
Вкладка, browser binding и controller не пересоздавались.

## Общая замена навыка

Общий backend/host recovery действует для всех интеграций, не только поиска.
Смысловую совместимость с уже порученной задачей оценивает модель; исполнение,
доступ и проверка release остаются у обычного host/provider. Отказ одной
реализации не требует отдельного выбора provider, если другая доступная
реализация укладывается в прежнее поручение. Явно выбранные сервис/аккаунт,
разрешённые получатели данных и расходы сохраняются. Неизвестную запись сначала
проверяют; замена навыка не разрешает duplicate send или обход admission.

Source gate и read-back опубликованных инструкций обязательны для выпуска.
Живые проверки остальных сервисов и current version выполняются отдельно;
результат Google не объявляется проверкой их актуального интерфейса.
