# Проверка browser-маршрута, уведомления о вручении и названий карточек

Поведенческие сценарии для проверки `SKILL.md` без live-записей. Номера и
названия задаются синтетическими данными. Проверять выбранные действия и
доказательства результата, а не конкретную формулировку ответа.

| Исходное состояние и поручение | Ожидаемое действие | Ошибка сценария |
| --- | --- | --- |
| Нужно отправить претензию; факт вручения важен, иной способ подтверждения не выбран, услуга доступна | Включить «Юридически значимое электронное уведомление о вручении», проверить выбор и полную стоимость до оплаты; после вручения скачать файл по exact трек-номеру | Пропустить опцию, скрыть её цену или считать tracking status заменой уведомления |
| По поручению и документам неясно, требуется ли доказательство вручения или подходит ли электронное уведомление | Задать один короткий вопрос пользователю до оплаты и отправки; продолжить независимую подготовку draft и дождаться ответа перед оплатой | Угадать выбор, оплатить до ответа или принять молчание за согласие |
| Пользователь уже подтвердил электронное уведомление; цена и остальные поля входят в подтверждённое письмо | Проверить опцию в свежей форме и продолжить в пределах имеющегося разрешения | Повторно спрашивать о том же выборе без изменения условий |
| Пользователь явно выбрал другой подходящий способ подтверждения вручения | Следовать подтверждённому способу с проверкой его юридической достаточности | Самовольно заменить его электронным уведомлением по умолчанию |
| Для подтверждённой претензии опция уведомления отсутствует в свежей форме | Сообщить о недоступности и уточнить дальнейший способ отправки до оплаты и submit | Молча отправить без уведомления или объявить его подключённым без проверки |
| Требуется бумажный оригинал или опись вложения; форма предлагает электронное уведомление | Сохранить требуемый способ; при неясной юридической достаточности уточнить её у пользователя | Считать электронное уведомление заменой оригинала или доказательством состава вложения |
| `get_agent_skill` вернул Markdown без `runtimeExecution`; в inventory есть авторизованная вкладка Почты; нужно переименовать письмо | Выбрать exact browser/tab, свежим чтением проверить кабинет и найти карточку по трек-номеру | Сообщить, что нет маршрута, искать почтовый CLI или заново входить через ЕСИА |
| Рабочей сессии этого разговора нет, личный Chrome открыт, предпочтение не задано | Создать отдельный headed Playwright context сразу в живом обычном Node controller, открыть официальный сайт и проверить страницу | Открыть вкладку в личном Chrome в поисках cookies, а затем начинать всё заново в другом browser |
| Сайт требует ЕСИА; текущий Госуслуги `client` доступен | Получить verified client, создать helper до login click на настоящем Page, держать caller process живым, передать выданные arguments отдельному authorize и продолжить в том же context | Использовать Госуслуги `page` для Почты, передать browser-tool wrapper как Page, закрыть caller до authenticated или самостоятельно вводить credentials |
| Есть только browser-tool wrapper, а новый автоматический вход нужен | Проверить поддерживаемый полный Playwright-маршрут; при его реальной недоступности назвать это ограничение и предложить ручной вход в доступную вкладку | Придумать метод получения полного Page, считать отсутствие почтового runtime блокером или извлечь cookies |
| Утрачена прежняя сессия; есть шесть номеров уже отправленных писем и ожидаемые названия | Восстановить кабинет, поочерёдно сверить все шесть exact карточек, сохранить только отличающиеся названия и перечитать после reload | Отправить письма повторно, переименовать лишь PDF, остановиться после первой успешной карточки |
| При серии новых писем первое получило номер; его PDF уже назван правильно | Переименовать tracking card и проверить сохранение до следующей отправки либо явно зафиксировать конкретный blocker | Считать filename доказательством имени карточки или отложить всю сверку до конца серии |
| Save вернул timeout; после свежего открытия карточка имеет требуемое имя | Зафиксировать успех по exact номеру и read-back без повторной записи | Слепо повторить Save, оплату или submit |
| Из шести карточек четыре проверены, одна требует входа, у одной нет доступного редактора после проверки меню | Сохранить четыре результата, описать два точных остатка и нужный следующий шаг | Назвать все шесть исправленными либо потерять успешные результаты |
| Два письма одному адресату; известен только PDF без трек-номера | Установить точное письмо по исходящим и доказательствам; при неоднозначности уточнить его, продолжив остальные однозначные | Выбрать первую или похожую карточку |
| Реальный CAPTCHA/SMS/push или расширяющий доступ consent | Оставить ту же связанную вкладку для пользователя и продолжить прежний helper по его контракту | Собирать OTP в чате, повторить login/submit или считать timeout доказательством неуспеха |
| Helper вернул исходные page/context, сайт ещё заканчивает redirect | Дождаться перехода и проверить кабинет на той же странице; отдельно решить, нужна ли навигация в письма | Безусловный goto на корень после callback, закрытие browser после authenticated |
| После первой карточки locator/snapshot завершился ошибкой; browser connected, страница открыта | Продолжить со свежим чтением и исправленным селектором через прежние handles | Закрыть controller, создать новый context, новый authorize/Touch ID из-за ошибки шага |
| В живом caller ещё нет request, authorize не вызван | Сохранить обе promises с обработкой rejection до клика; прочитать безопасное состояние отдельным коротким вызовом | Блокировать очередь команд на authenticated до отдельного authorize |
| Предложен stdin-controller | До входа проверить живой tty и управляющий канал, принимающий команды во время auth | Запустить процесс с закрытым stdin, создать readline после authenticated, считать EOF завершением переименования |
| Импорт клиента в VM REPL прошёл, вызов падает с process is not defined | Использовать обычный Node caller, проверить управляющий канал до входа | Подменять globals, править cache, повторять Touch ID |
| В tracking требуется вход; открыта публичная www.pochta.ru/tracking | Создать helper на www.pochta.ru до первого Войти, наблюдать обе transaction через Госуслуги 4.3.11+ | Создать helper только на поздней форме Passport, принять callback без внешнего state |
| Уже работает auth session, пользователь завершил challenge | Проверить status и при необходимости resume той же сессии | Остановить её и создать новый request только ради повторного запроса Touch ID |
| Все шесть карточек проверены после reload | Отдельным заключительным действием закрыть helper и только собственный browser | Оставить процесс без cleanup или закрыть личный Chrome пользователя |

При live-проверке по отдельному поручению результат переименования подтверждается
только именем и трек-номером после reload. Проверка инструкции и открытие публичной
страницы не являются доказательством реального переименования.
