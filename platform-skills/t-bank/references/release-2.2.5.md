# Т‑Банк 2.2.5

## Что исправлено

Runtime 1.2.5 больше не принимает первую размеченную OTP-ячейку T‑ID за одно
поле. При точном TOTP challenge он выбирает всю группу из шести видимых safe
inputs и вводит по одной цифре в каждую последовательно включаемую ячейку.

Проверены статически остальные переходы делегированного входа: российский
телефон, optional username, password с именованным либо безымянным submit,
одно поле TOTP, шесть ячеек TOTP, ручные SMS/app-коды, optional quick PIN,
consent, callback и fast SSO. Их правила и запрет слепого повтора не менялись.

## Миграции и env

Повторный setup, перенос vault, DB migration и новые env не нужны. Сохранённый
TOTP seed остаётся в прежнем encrypted vault. Minimum host – 1.6.17. Версия
skill – 2.2.5, runtime – 1.2.5.

## Проверка после публикации

По прямому запросу владельца автоматические проверки не запускаются ни локально,
ни в GitHub Actions. Приёмка – один новый реальный T‑ID flow на current 2.2.5.
Незавершённую transaction прежнего runtime нужно остановить: новый helper не
может безопасно подхватить её с середины.

## Rollback

Остановить незавершённый authorizer и выпустить новый immutable runtime. Не
переносить tag, не стирать encrypted vault и не повторять login/TOTP submit
после неизвестного результата.
