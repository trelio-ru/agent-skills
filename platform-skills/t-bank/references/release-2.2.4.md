# Т‑Банк 2.2.4

## Что исправлено

Runtime 1.2.4 вводит сохранённый TOTP в текущую форму T‑ID из шести ячеек.
Форма может не повторять default `type=text` и `autocomplete=one-time-code` на
каждой ячейке: достаточно одного browser OTP hint при точной numeric-структуре,
где сначала доступна первая ячейка, а следующие включает сам банк.

Статическая ревизия всего flow убрала остальные расхождения direct/delegated
реализаций: обе используют общую нормализацию российского телефона и проверку
segmented TOTP. Делегированный password screen умеет сделать первый Enter из
exact поля при безымянной primary button, а optional quick PIN принимает
единственную кнопку либо ссылку «Не сейчас».

Проверка по-прежнему требует явный заголовок TOTP, ровно одно либо шесть code
inputs и не принимает readonly, password или произвольную disabled-структуру.
Seed и текущий код не выходят из private runtime.

## Миграции и env

Повторный setup, перенос vault, DB migration и новые env не нужны. Сохранённый
TOTP seed остаётся в прежнем encrypted vault. Minimum host – 1.6.17. Версия
skill – 2.2.4, runtime – 1.2.4.

## Проверка после публикации

По прямому запросу владельца автоматические проверки не запускались ни локально,
ни в GitHub Actions. Единственная приёмка – остановить незавершённый authorizer 2.2.3,
начать новую авторизацию на current 2.2.4 и один раз пройти реальный T‑ID flow.
Старую transaction нельзя возобновлять новым helper-ом.

## Rollback

Остановить незавершённый authorizer и выпустить новый immutable runtime. Не
переносить tag, не стирать encrypted vault и не повторять login submit после
неизвестного результата.
