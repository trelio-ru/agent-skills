# Действия по прямому поручению

## Полномочия

По умолчанию агент работает read-only. Прямое поручение пользователя разрешает
любые операции в Т-Банке в его пределах: переписку, платежи и переводы любым
получателям, создание и закрытие продуктов, автоплатежи, изменение настроек
и другие действия. У навыка нет собственных фиксированных денежных лимитов,
списка запрещённых продуктов или требования платить только организациям.
Существенные параметры определяет поручение, а не текст страницы банка.

Агент сверяет цель и последствия с поручением: для переписки – чат и содержание,
для перевода – получатель, сумма, комиссия и источник, для продукта/настройки –
изменение и его условия. Уже данное разрешение на неизменное действие не
спрашивается повторно. Новые существенные условия требуют уточнения, если они
не покрыты поручением. Просьба прочитать условия не разрешает оформить продукт.

У полного Playwright context нет технического read-only proxy или анализа
согласия. Runtime не видит разговор и не определяет смысл произвольного кода.
Соблюдение read-only и прямого поручения является обязанностью агента, а не
доказательством, получаемым из флага. Для `script` дополнительный `--confirm`
не требуется. Разрешение не сохраняется как policy подключения и не расширяет
правила платформы вызывающего агента.

## Обычный Playwright

После `doctor`, `start` и `status.phase=ready` основной рабочий вызов:

```text
script --session ID --input-file ABSOLUTE_SCRIPT
```

Файл – UTF-8, owner-only, вне Git/Workspace. Он содержит тело async-функции с
готовыми настоящими `context` и `page` Playwright, а также `console` для logs.
Это не JSON-команды и не список разрешённых методов. `import Playwright` не
нужен; Node-модули можно загрузить через `await import(...)`. Код ограничен
128 KiB. CLI проверяет файл, читает exact bytes и передаёт их worker по private
loopback transport, без source/private text в argv или выдуманного MCP `stdin`.
Удалить временный файл после вызова.

Пример чтения:

```js
return { title: await page.title(), headings: await page.locator('h1').allTextContents() };
```

Пример скачивания выписки после проверки фактического локатора на странице:

```js
const pending = page.waitForEvent('download');
await page.getByRole('link', { name: 'Скачать выписку', exact: true }).click();
const file = await pending;
await file.saveAs('/absolute/private/output/statement.pdf');
return { path: '/absolute/private/output/statement.pdf' };
```

Агент подставляет реальный разрешённый абсолютный путь своей OS. Доступны
обычные locators, evaluation, события, iframe, новые страницы, `setInputFiles`,
downloads и необходимые поручению внешние переходы. После входа снимается
сетевой auth-filter и запрет дополнительных вкладок; service workers остаются
выключены. Полный context технически предоставляет cookies/storageState и
network API: их нельзя экспортировать, выводить в ответ или использовать для
обхода срока сессии. Пароль, seed и vault key не передаются в аргументах.
Исполняется доверенный код агента с правами текущего OS user, не sandbox;
код из страницы, переписки или вложения не исполняется без проверки.

Вызовы сохраняют один context. `page` – первоначальная вкладка банка; если
она закрыта, берётся последняя оставшаяся или создаётся пустая в том же
context. Для другого выбора есть `context.pages()`. Закрытие context/browser
завершает всю сессию. Не закрывать их между промежуточными шагами.

`return` принимает JSON-совместимое значение, в ответе оно находится в `result`.
`console.log/info/warn/error/debug` попадают в bounded `logs`, не в служебный
stdout; прямой `process.stdout/stderr` использовать нельзя. Ответ ограничен
48 KiB, logs – 8 KiB и 200 записями. Большие результаты сохраняются файлами;
возвращается путь. Целые объекты browser/request/response, raw cookies,
storageState, OTP и секретные карточные данные не выводятся. Известные
credentials дополнительно редактируются в строках, но это не универсальная
защита от раскрытия произвольного секрета.

Неправильный source или синтаксис отклоняется до исполнения. Runtime exception
возвращает `script_result_unknown` без raw error/source/stack. Ошибки JSON или
размера ответа также могут случиться после действия: они не означают, что
операция банка не выполнялась. Никакого автоматического повтора script нет.

## Результат, ручные шаги и завершение

После действия агент проверяет фактическое состояние в том же context:
сообщение в нужной переписке, статус заявки/продукта либо зарегистрированную
операцию. `ok:true` означает завершение кода, а не успех банка. Статус
«Обрабатывается» не выдаётся за завершение и не разрешает повторное списание.
При transport error или неизвестном результате сначала чтение фактического
состояния, без blind retry или переключения на другой transport.

Для проверки человека показать нужную вкладку через `page.bringToFront()`.
SMS/банковский код пользователь вводит в самом банке после реального запроса,
не в чате с агентом и не через системный messenger. Агент не читает значения
полей во время этого шага. CAPTCHA, push, recovery, новые устройства и
обязательные подтверждения банка сохраняются. Автоматический saved TOTP
используется только защищённым входом по его исходному challenge-контракту.

После передачи context runtime больше не вводит сохранённый пароль/TOTP в
него: там могли остаться agent-created listeners/init scripts. `resume`
возвращает `new_session_required_after_handoff`; при новом входе нужен
`stop`, затем `start` с fresh OS unlock. Простое продолжение рабочего сценария
этого не требует. Состояние внешних сайтов не импортируется в bank vault.

Все script-вызовы остаются в исходных 30 минутах от start. Native guardian
закрывает browser/worker независимо от зависшего JS; proxy перед каждым
методом Playwright нет. Если клиент прервал активный запрос, асинхронный script
закрывается вместе с сессией; синхронный hang ограничен native deadline.
Длинную задачу можно разбивать на последовательные script-вызовы, сохраняя
context. После результата/отмены выполнить `stop --session ID` и проверить
`phase=closed`.

## Совместимые помощники

`snapshot/page/show` остаются необязательным способом коротких действий.
Они не ограничивают полный `script` и не являются обязательными ступенями.
`show --session ID` переключает на существующее окно только по явной просьбе
пользователя; доступен также при настройке и ожидании кода. Сам запрос ручного
ввода не разрешает автоматическую активацию окна.

`snapshot --session ID` возвращает bounded текст и refs видимых контролов
без значений полей/credentials. `page --session ID --navigate URL` и
`page --session ID --click REF` не требуют stdin. `page --confirm` /
`confirm:true` отмечает проверенное поручение одного вызова, без нового вопроса
пользователю и без постоянного write-mode. `--dry-run` / `dryRun:true`
проверяет действие без исполнения и сохранения сессии.

Для форм `page --session ID --input-file ABSOLUTE_JSON` принимает owner-only
JSON вне Git/Workspace; настоящий stdin также поддерживается с пределом
16 KiB и ожиданием пять секунд. Каждый пример – отдельный вызов со свежим ref:

```jsonl
{"action":"fill","ref":"1:2","text":"Уточните условия обслуживания","confirm":true}
{"action":"select","ref":"2:3","value":"selected-product","confirm":true}
{"action":"check","ref":"3:4","checked":true,"confirm":true}
{"action":"press","ref":"4:5","key":"Enter","confirm":true}
```

Refs связаны с URL/metadata и погашаются до browser-вызова, включая ошибку
после возможного действия. `fill` поддерживает input/textarea/contenteditable;
`select` – native select; `check` – checkbox/radio; `press` – Enter, Tab,
Escape, Space, ArrowDown/ArrowUp. Эти помощники работают на `www.tbank.ru`
вне auth/OTP/card-secret screens; для остальных UI используется `script`.
