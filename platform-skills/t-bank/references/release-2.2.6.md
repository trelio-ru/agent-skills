# Т‑Банк 2.2.6

## Что исправлено

Runtime 1.2.6 больше не останавливает delegated T‑ID на ложном
`user_required`, когда после отправки телефона, пароля или сохранённого TOTP
форма кратко заменяется пустым same-origin document. В течение ограниченного
перехода runtime ждёт следующую известную форму либо проверенный callback.

Флаги уже введённых телефона, пароля и TOTP сохраняются. Неизвестный результат
не приводит к повторному вводу или повторному submit. Настоящие SMS/app-коды,
consent, CAPTCHA и security challenge остаются ручными; `status` сообщает только
фиксированную безопасную причину без DOM, кода или credential values.

## Миграции и env

Повторный setup, перенос vault, DB migration и новые env не нужны. Сохранённый
TOTP seed остаётся в прежнем encrypted vault. Minimum host – 1.6.17. Версия
skill – 2.2.6, runtime – 1.2.6.

## Проверка после публикации

По прямому запросу владельца автоматические проверки не запускаются ни локально,
ни в GitHub Actions. Tagged workflow только собирает immutable package. Приёмка –
один новый реальный T‑ID flow на current 2.2.6 без повторения уже завершившихся
шагов.

## Rollback

Остановить незавершённый authorizer и выпустить новый immutable runtime. Не
переносить tag, не стирать encrypted vault и не повторять login/TOTP submit
после неизвестного результата.
