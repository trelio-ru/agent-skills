# Госуслуги 4.3.3

## Исправление входа в Почту России

Runtime 3.3.3 различает две вложенные OAuth-транзакции Почты. На публичной
странице заказных писем `zakaznoe.pochta.ru` сначала открывает Post ID через
`passport.pochta.ru/oauth2/authorize` со своим `state` и возвратом в
`zakaznoe.pochta.ru/oauth2/cb`. Затем паспорт открывает ЕСИА с другим `state`
и возвратом в `passport.pochta.ru/pc/ext/v1.0/authorize/esia`. Post ID request
больше не ошибочно считается ответом ЕСИА. Вход в сервис писем подтверждается
после проверенных HTTP ответов обеих транзакций и document commit; один ответ
ЕСИА не считается готовностью кабинета писем.

## Проверка

Старый runtime на реальном публичном переходе Почты воспроизвёл
`service_callback_rejected` до страницы ЕСИА. Новый runtime в том же браузерном
сценарии дошёл до настоящего запроса ЕСИА. Оставшуюся часть проверяют тесты с
двумя разными `state`, обоими callback, неверным порядком, подменой и повтором.
Реальный защищённый вход и создание письма требуют отдельной проверки в рабочей
сессии; публичный smoke не вводит пароль и не отправляет письмо.

Карта доменов и разрешение на вход остаются прежними. Навык Почты России и его
подготовленные комплекты не меняются.
