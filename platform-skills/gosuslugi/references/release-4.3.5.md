# Госуслуги 4.3.5

## Продолжение после ручного шага ЕСИА

При делегированном входе runtime 3.3.5 замечает отправку ручной проверки в
том же окне ЕСИА и один раз продолжает уже начатую авторизацию. Проверенный
callback также завершается автоматически. Команда `resume` остаётся для ручного
шага без отправки формы. Повторный вход, новый браузер и перенос сессии между
профилями не выполняются.

## Проверка

В реальном headed Chrome проверен синтетический сценарий: окно ЕСИА запрашивает
ручную проверку, пользовательская кнопка отправляет POST, тот же authorizer
продолжает вход и возвращает исходные Page/Context. Остальные сценарии
авторизации и локального browser runtime прошли regression на macOS.
На живой Почте переход дошёл до окна ЕСИА, но полный вход и кабинет заказных
писем после ручной проверки пока не подтверждены.
