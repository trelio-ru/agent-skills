## Форма обращения ПОС

Для порученной подачи используй `createPosSubmission` из `modulePath` штатной
команды `client`. Это исполняемый сценарий того же signed package, поверх
защищённого ЕСИА. Не переписывай его guards в одноразовый caller и не заменяй
его цепочкой новых входов. API ниже относится только к точной публичной форме
`https://pos.gosuslugi.ru/form/?opaId=...`; прочие сайты остаются у caller.

### Подготовка и одноразовая подача

Заполни и сверь адресата, текст, регион, категорию/подкатегорию, режим 59-ФЗ и
приложения в одной caller-owned Page. Оригиналы файлов и их SHA-256 сверяются
до загрузки; fingerprint `review` проверяет текущие значения формы и metadata
выбранных File, но не заменяет проверку bytes исходных документов.
Разрешение пользователя на эту конкретную подачу переиспользуется из разговора.
При неизвестном результате прежней попытки сначала проверяется регистрация
исходной подачи; новая форма и новый экземпляр API не разрешают повтор.

```js
const { createPosSubmission } = await import(pathToFileURL(client.modulePath).href);
const submission = createPosSubmission(page, {
  ...client.options, configHome: client.configHome, confirm: true,
});
// inputId берётся из текущей формы. Индексы option-N не закрепляются:
// асинхронное обновление списка может поменять соответствующий им вариант.
await submission.select({ inputId: 'react-select-2-input', label: 'Согласованный регион' });
// Только когда этот режим согласован; check-agree метод не трогает.
await submission.setFederalLaw({ enabled: true });
const reviewed = await submission.review();
// review не нажимает кнопок и не принимает согласие. Покажи ту же форму
// только если её check-agree ещё не отмечен пользователем. Наблюдай изменение
// через inspect(), без обязательного ответа «готово» и без новой формы.
// После согласия и проверки уже данного поручения:
await submission.start({ reviewed: reviewed.reviewId, confirmSubmission: true });
// start возвращается после первого click, не блокируя очередь на ESIA.
// Последующие advance() выполняют только ещё не отправленный modal/role click.
// authorization.phase=esia_authorization_required содержит request.arguments:
// передай их без изменений тому же verified runtimeExecution.localAction.
// После authorize продолжай advance()/inspect() на ЭТОМ ЖЕ submission.
const result = await submission.advance();
```

Сценарий сам связывает один helper до первого click и однократно выбирает
единственную явную карточку физического лица внутри ПОС после возврата ЕСИА.
Не выбирает организацию по имени и не принимает согласие пользователя.
`reviewId` проверяется перед click; изменившуюся форму нужно заново сверить
через `review()` того же объекта. Ожидание личной галочки сохраняет review,
Page, приложения и остальные значения. Ошибка preflight до входа исправляется
в этой же форме; новый helper для неё не требуется.

`select({inputId,label})` выбирает exact label внутри связанного React Select
и проверяет выбранное значение после click. `setFederalLaw({enabled})`
идемпотентно выбирает уже согласованный режим рассмотрения по 59-ФЗ через
штатный input; скрытый checkbox не является поводом передавать этот шаг человеку.
Оба метода до входа аннулируют старую review и сохраняют остальные поля.

`advance()` возвращает текущую фазу и делает только допустимый следующий
однократный шаг. `inspect()` и `wait({timeoutMs:30000})` – только чтение;
ожидание ЕСИА/человека не становится отказом или новым разрешением на вход.
Не завершай поручение после callback: продолжай исходный сценарий до
`phase=submitted` с `receipt.registrationNumber` либо до конкретного blocker.
`close()` отключает свой helper/observer; браузер закрывает caller после
сохранения результата. Закрытие и новая попытка не продлевают исходную lease.

### Подтверждение и диагностика

Успех требует регистрационного номера в штатном feedback-блоке этой формы,
связанного с наблюдённым единственным `POST /inbox-service/appeals` той же
основной Page. Callback, HTTP 200, закрытие popup и возврат к форме успехом
не являются. Предсуществующая квитанция без такой связи – только lead для
проверки, а не подтверждение текущего заявления.

Виджет загружает выбранные файлы одновременно через Promise.all. Сценарий
пропускает эти же исходные `POST /inbox-service/filestorage` последовательно,
с интервалом не меньше секунды после ответа предыдущей загрузки. Payload,
имена и bytes не меняются; новых запросов либо retry код не создаёт.
Отказ загрузки прекращает ещё не отправленную очередь. Это не доказательство
причины любого HTTP 403 и не обход серверного запрета. Внутри route handler
не ожидается завершение того же request: очередь продолжается по отдельным
response/failure событиям. Cleanup сохраняет наблюдение до конца текущей
операции, снимает route и закрывает helper независимо от ошибок.

Наблюдение сохраняет только числа HTTP, факт dispatch/transport failure и
этап `token_exchange|user_info|attachment_upload|appeal_create`. Body, headers, токены, OAuth
query, auth DOM и raw browser exceptions не читаются и не возвращаются.
Виджет ПОС может скрыть ошибку создания и снова показать кнопку входа;
это не повод нажимать её повторно. `outcome=unknown` сохраняет запрет replay.

- `pos_http_failure` – проверяй stage и HTTP evidence той же попытки
- `pos_action_timeout|pos_action_failed` – проверяй operation и бизнес-результат;
  ошибка click после возможного dispatch не разрешает его повтор
- `pos_create_not_observed` – после возврата и выбора роли запрос создания не
  наблюдался за bounded ожидание; выясни причину в этой же форме
- `pos_submission_unverified` – запрос наблюдался, квитанция не получена;
  продолжай read-back, без повторной отправки
- `pos_upload_result_unknown` – не получен проверяемый исход загрузки файла;
  не отправляй заявление с неполным комплектом и не запускай новый вход
- `pos_multiple_create_requests` – номер одной квитанции не исключает дубль;
  сохрани её и проверь исход всех наблюдённых запросов
- `pos_review_changed|pos_consent_required|pos_form_not_ready` – исправь
  preflight той же формы; это ещё не отправка и не отказ ЕСИА

Запрет replay сохраняется и после timeout/cleanup. Поздний проверенный номер
может подтвердить одну отправку, но не скрывает несколько запросов создания.
Сохрани номер, время, адресата и свидетельство в каноническом контексте задачи.
Списки других кабинетов, не учитывающие ПОС, не доказывают отсутствие подачи.

### Заполнение встроенными командами

Регион в выпадающем списке выбирается в два действия: введи название через `page --input-file`, получи свежий `snapshot` и нажми reference нужного варианта с `role=option` через `page --click REF`. После этого проверь, что регион сохранился в форме. Один ввод фильтрует список, но не выбирает значение. Не придумывай Enter/keyboard-команды; если нужного варианта нет в свежем снимке, сообщи точный технический блокер.

При подготовке `https://pos.gosuslugi.ru/form/?opaId=...` встроенными командами используй обычный запуск с TITLE по шагу 2, дождись готовности Госуслуг и перейди через `page --navigate` к точному адресу формы. Заполни доступные поля и проверь их до попытки входа в сам виджет. Эта форма рассчитана на порядок «заполнение → авторизация → отправка»; отдельная авторизация перед заполнением не нужна. `phase=ready` после перехода подтверждает доступность рабочих команд, а не вход на каждой открытой странице.

Нижняя кнопка «Войти через Госуслуги» рядом с текстом «Ваше сообщение будет направлено после авторизации» запускает процедуру подачи: после ЕСИА виджет автоматически создаёт обращение. Это не обычная кнопка входа. Не нажимай её для проверки авторизации и не проси пользователя нажать её до заполнения и итоговой сверки адресата, текста, приложений и режима подачи. Не принимай согласие с правилами ради включения кнопки. В режиме встроенных команд после подготовки человеку передаётся именно финальный шаг «войти и отправить», а не дополнительная промежуточная проверка входа.

`manual_confirmation_required` означает, что action gate отклонил потенциально значимый control; один этот код не объясняет юридический смысл кнопки и не доказывает обязательность ручного ЕСИА-входа. Сначала проверь видимый контекст. Обычный поддерживаемый переход к ЕСИА выполняет runtime; согласие, подпись и финальная подача имеют отдельные границы. Встроенные команды не управляют auth popup. Полный Playwright-сценарий поддерживает такое окно через `createEsiaAuthorization` на исходной форме **до** нижней кнопки и последующего входа в modal. До этих clicks нужны итоговая сверка и прямое разрешение на конкретную подачу: после возврата виджет отправляет её автоматически. Callback не доказывает регистрацию: проверь номер/статус на исходной странице; при неизвестном результате не повторяй вход или submit. Начатый старым helper-ом popup нельзя восстановить новым задним числом. После результата/отмены заверши свой сценарий; для обычного `start` выполни `stop` и проверь `closed`.
