# Госуслуги 2.2.1

Обновление только инструкции с переиспользованием подписанного runtime 1.2.0.
Tagged package повторно не публикуется: immutable instruction-only release
использует штатную internal-admin публикацию с exact current CAS и последующим
чтением каталога. Нового OS unlock либо обновления исполняемых файлов не требует.

Виджет ПОС заполняется до собственной авторизации. Нижняя кнопка «Войти через
Госуслуги» совмещена с последующей отправкой; она не является предварительным
входом. Инструкция теперь требует сначала заполнить и сверить обращение и лишь
затем передать финальный шаг человеку. Кода `manual_confirmation_required`
недостаточно, чтобы объяснять пользователю смысл кнопки или объявлять любой
ЕСИА-переход обязательным ручным действием.

Основание: анонимный live probe exact формы подтвердил disabled button вне
HTML form и отдельный unchecked checkbox правил. Публичный
`main.30686a01.chunk.js` подтверждает цепочку auth callback → token/user-info →
`P.create` для `inbox-service/appeals`. Ни согласие, ни подача, ни настоящий
ЕСИА-вход в этой проверке не выполнялись. Корневой POS ведёт в backoffice,
который не используется как обход для заявителя.

Runtime gate, popup policy, credentials, vault, native unlock и срок сессии
остаются прежними. Поддержка автоматической финальной подачи не заявляется.
