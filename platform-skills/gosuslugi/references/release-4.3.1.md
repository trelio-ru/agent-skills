# Госуслуги 4.3.1

## Переиспользование активной сессии для ЕСИА

Runtime 3.3.1 принимает один exact delegated `authorize` в уже работающем
обычном worker с фазой `ready`. Он повторно проверяет private authorization
descriptor внутри worker, использует уже разблокированные credentials и native
permit, а после verified callback возвращает обычную сессию в `ready`.

Новый OS unlock, второй browser/worker и остановка активной сессии не нужны.
Текущая страница Госуслуг, browser context и несохранённая форма сохраняются.
Одновременная вторая transaction, несовпадающая identity, истёкший descriptor
или неготовая сессия блокируются fail-closed.

Неопределённый результат автоматического распознавания больше не называется
ручным шагом. Runtime возвращает `review_required` и безопасный public-page
snapshot модели, не выводя окно на передний план; запрос пользователю допустим
только для конкретно распознанного challenge.

Старый macOS guardian/v1 helper остаётся побайтно совместимым с опубликованным
runtime 3.2.0. Новый отдельно замороженный key-only helper использует v2
Keychain service и показывает bounded название текущего разговора в Touch ID,
не сохраняя его. При наличии прежнего vault старый доверенный helper один раз
читает v1 key после обычного Touch ID и передаёт его новому через private stdin;
изменённый бинарник никогда не читает v1 item, поэтому запрос пароля login
Keychain не появляется. Все последующие запуски используют v2 с названием
разговора. Автоматический delegated-вход в уже готовой сессии не вызывает новый
OS prompt вообще.

## Миграции и совместимость

Vault ciphertext, browser snapshot и env не меняются. macOS один раз создаёт
v2 Keychain item с тем же ключом; v1 сохраняется для rollback и удаляется вместе
с v2 только явным `forget`. Windows продолжает использовать тот же DPAPI record,
а название разговора передаёт CredUI через stdin. Отдельный auth-only запуск
остаётся совместимым для случая, когда обычной готовой сессии нет. Minimum host
остаётся 2.4.0. Версия skill – 4.3.1, runtime – 3.3.1.

## Проверка после публикации

Помимо полного security gate нужен сквозной headed smoke: первый migration
unlock не должен открывать password dialog Keychain, следующий запуск должен
показывать название разговора в Touch ID, затем вход ГАС должен завершиться
через тот же `sessionId` без нового системного prompt, а исходная сессия после
callback должна остаться `ready`. Фокус до обязательного ручного challenge не
меняется.

## Rollback

Остановить незавершённую transaction и выпустить новый immutable runtime. Не
переносить tag, не стирать encrypted vault и не повторять credential input или
submit после неизвестного результата.
