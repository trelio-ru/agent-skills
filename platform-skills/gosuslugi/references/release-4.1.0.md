# Госуслуги 4.1.0

## Что вошло в релиз

Runtime 3.1.0 поддерживает ЕСИА в отдельном окне, которое открыла исходная
страница того же Playwright context. Один помощник создаётся до штатного
клика и обслуживает same-page либо direct-popup вход. После exact callback,
успешного HTTP ответа и document commit он возвращает исходные context/page;
текст формы и выбранные файлы сохраняются. Самозакрытие callback popup и
быстрый SSO не требуют нового окна, повторного ввода или отправки.

Чужие, заранее открытые и вложенные окна не принимаются автоматически.
Второе окно авторизации, подмена callback и закрытие до проверенного возврата
прекращают помощник, сохраняя браузер вызывающего сценария. Callback запрещает
следующий символ ещё до смены URL. Гонка финального TOTP-ввода с закрытием
окна переводит authorizer к ожиданию результата без повторной операции.

Создание private native cache работает и при стандартной политике чистой
Windows: выполнение разрешается только дочернему процессу с проверенным
package script, без изменения постоянных настроек PowerShell.

## Миграции и env

Повторный setup, перенос vault, DB migration и новые env не нужны.
Minimum host – 1.6.17. Отдельный browser Agent Skill не добавляется.
Клиент импортируется по exact пути нового verified package; уже начатая
старая OAuth transaction автоматически не восстанавливается.

## Что проверить после деплоя

Каталог возвращает 4.1.0/runtime 3.1.0 и exact package digest. Проверить signed
`client`, same-page и direct-popup вход после разрешения на конкретный сайт.
На macOS/Windows CI проверяет password/TOTP/SSO, native permits, callback
race, исходную форму и файлы. Синтетический CI не доказывает реальный вход.
Для ПОС отдельно проверить регистрацию согласованного обращения: callback
не равен подаче, а нижняя кнопка запускает процедуру отправки после входа.

## Rollback

Завершить помощник без закрытия caller-owned формы и выпустить новый immutable
runtime с исправлением. Не переносить tags, не стирать encrypted vault и не
повторять подачу после неизвестного результата. Встроенные `start`/`page`
сохраняют прежние ограничения; сайт и действия остаются у caller-сценария.
