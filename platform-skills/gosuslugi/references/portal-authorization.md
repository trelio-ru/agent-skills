## Авторизация

1. Используй один выделенный runtime context и продолжай действие в той же сессии после ЕСИА.
2. По умолчанию выбирай роль физического лица; организацию – только по прямой просьбе.
3. Обычные password/TOTP формы проходит только защищённый runtime. При неизвестной форме он останавливается для человека, не угадывает поле пароля и не делает повторную отправку после неизвестного результата.
   На штатном QR-экране с единственной видимой кнопкой «Логин и пароль» runtime сам выбирает парольный вход, даже когда ниже перечислены биометрия и другие способы. Это действие лишь меняет способ входа; отдельные CAPTCHA, push/SMS, согласие и выбор личности остаются ручными.
4. Не меняй сетевой маршрут автоматически. Transport failure не доказывает неверный пароль, потерю сессии или необходимость повторного setup. У нового runtime нет proxy/headless/plaintext fallback.
