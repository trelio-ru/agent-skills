## Самостоятельная проверка экрана роли

При непонятном `role_choice_required` делегированного входа до вопроса
пользователю сам вызови `review-role --session AUTH_SESSION_ID` через тот же
localAction. Команда заново осматривает связанную вкладку и возвращает только
`roleReview.state` и число карточек физлица; auth DOM, имена, поля и URL
не выводятся. Это осмотр, он не выбирает роль и не повторяет вход.

При `personal_available` выполни один `resume` той же auth-сессии: default
физлицо уже разрешено. `choice_dispatched` требует ожидания callback без
повторного клика. При `missing_card` ограниченно подожди и повтори осмотр;
отсутствие загруженной карточки – технический блокер, не просьба выбрать её
вручную. `returned` требует проверки результата на рабочей странице.
`ambiguous_card`, `disabled_card`, `unsupported_card`, `unsupported_screen`
и `authentication_fields_present` сохраняют точный предел диагностики;
не выдумывай пользовательский шаг. Проси участие только для установленного
challenge или выбора между несколькими личностями, который нельзя разрешить
по поручению. Не запускай `roles`/`choose-role` в caller-owned браузере,
не снимай auth DOM/screenshot и не создавай новый helper ради ошибки команды.
