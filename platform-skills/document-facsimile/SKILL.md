# Факсимиле для документов

Каждое факсимиле – отдельный личный аккаунт навыка. Компания подключает навык
по обычному контракту Trelio; каждый пользователь на своём устройстве добавляет
свои аккаунты. Изображения подписей не входят в пакет, каталог Trelio или
Workspace. Подробный runtime/storage/документный контракт –
[references/workflow.md](references/workflow.md).

## Запуск и выбор аккаунта

Один раз перед первой командой сессии загрузи `get_agent_skill` с
`sections=[instructions,execution]` в точной компании/проекте. Выполняй только
возвращённый verified `runtimeExecution.localAction`; не вызывай скрипт напрямую.
Host управляет допуском до 12 часов без продления при чтении. При том же scope,
навыке, release и намерении не повторяй `get_agent_skill` перед каждой
подкомандой. Перечитай после новой сессии, утрате полного текста или compaction,
через 12 часов, смене scope/route, устранении setup/access blocker и один раз
при `AGENT_SKILL_RELEASE_CHANGED`.

Начни с общего `account list`. Выбирай по ФИО владельца из `show`, названию и
комментарию аккаунта; один человек может иметь несколько вариантов подписи.
Имя/комментарий редактируются общими `account create/update`, привязка –
`account bind/unbind/default`. При каждом использовании передавай host-у точный
`--local-account UUID`. Общий default не заменяет проверку автора документа.
Несколько подходящих вариантов без ясного условия в комментариях требуют
короткого вопроса о выборе, а не случайного первого аккаунта.

Новый аккаунт: узнай название и условия применения, затем `account create`
с name/comment и текущей revision каталога. `configure` открывает локальную
форму: пользователь выбирает прозрачный PNG, прямо указывает **ФИО владельца**
и ширину (обычно 30–38 мм). ФИО обязательно; отчество указывается, если есть.
Не угадывай ФИО по рисунку или имени файла, не проси изображение подписи через
чат. Для каждого факсимиле условия применения хранятся в его комментарии,
а общие предпочтения пользователя – в существующих личных правилах навыка.

Ожидающий `configure` возвращает проверенный `configured`, `cancelled` или
ошибку. После сохранения продолжи уже разрешённую работу без обязательного
«заполнил». При timeout/потере процесса сначала `doctor`: неизвестный исход
не разрешает повторно перезаписать настройку. Ошибка прав/политики устройства
требует устранения причины; не обходи защиту другим storage или транспортом.

## Применение

1. Определи документ, автора/подписанта, формат, место подписи и разрешение
   использовать факсимиле для этой работы. Наличие PNG или комментария аккаунта
   само по себе не разрешает подписывать будущие документы. Уже данное точное
   поручение или применимое правило достаточно – повторное согласие не нужно.
2. Проверь полное ФИО автора против `show`. Инициалы, неоднозначный подписант,
   несовпадение или несколько людей с одинаковым ФИО требуют уточнения.
   Учитывай личные правила навыка и комментарий выбранного аккаунта.
3. Для DOCX подготовь **одну** метку `{{SIGNATURE}}` в проверенном месте подписи.
   `insert-docx --input <local.docx> --output <new.docx> --author <ФИО> --authorized`
   создаёт отдельный файл. Метка может быть разделена между обычными runs Word.
   Сложная разметка/несколько меток – blocker; сначала приведи только выбранное
   место к поддерживаемой разметке в копии документа.
4. Для PDF или другого редактора `image --author <ФИО> --output <local.png>
   --authorized` создаёт owner-only локальную копию PNG. Используй доступное
   документное средство для точного размещения с пропорциями и шириной из `show`.
   Экспортируй PNG во временную локальную папку вне Git/Workspace; после
   вставки удали эту промежуточную копию. Не загружай отдельный PNG в Trelio.
   Для Google Docs при наличии подходящего средства используй подготовленный
   DOCX и проверяй результат импорта. Сам навык не отправляет файлы во внешние сервисы.
5. Отрендери результат и визуально проверь размер, читаемость, положение подписи,
   ФИО и даты. Не перекрывай текст и не меняй подписанта. Отдавай документ после
   проверки; промежуточный PNG не прикладывай к сообщению по собственной инициативе.

`--authorized` отражает имеющееся основание для этой операции; агент не ставит
флаг по одному факту настройки аккаунта. Доставка готового документа требует
своей обычной авторизации. Самостоятельное раскрытие отдельного изображения
подписи другому пользователю/компании также требует прямого поручения.

В черновиках и внутренних аналитических заметках автоматически факсимиле не
ставится. Имя итогового файла описывает документ; не добавляй слова
«факсимиле»/`facsimile`/`faksimile` без запроса. Изображение подписи не является
криптографической электронной подписью; не представляй вставку PNG как ЭП.

`doctor`/`show` показывают readiness, ФИО, размер и revision, без PNG/base64
и private storage path. `clear --expected-revision N --confirm` очищает
локальные PNG/ФИО только по прямому запросу пользователя. Аккаунт в общем
каталоге остаётся; его company binding меняется отдельно штатными командами.
