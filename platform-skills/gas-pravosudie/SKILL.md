# ГАС «Правосудие»

## Основное правило

Работай только на официальных HTTPS-доменах `sudrf.ru` и их поддоменах.
ЕСИА вызывай только через текущий verified runtime Госуслуг. Пароли, OTP/TOTP,
cookies, tokens, authorization code, закрытые ключи, сырые данные сессии,
auth DOM и сетевые тела нельзя помещать в prompt, чат, логи, Workspace или Git.

Просьба проверить личный кабинет, обращение, дело либо выполнить другое действие,
для которого нужен кабинет, уже разрешает обычный вход. Не задавай отдельный
вопрос «можно ли войти» и не проси пользователя нажимать штатную кнопку входа.
Точный стандартный checkbox ГАС рядом с единственной ссылкой «Пользовательское
соглашение» runtime отмечает сам как техническую предпосылку поручения. Если
текст, набор checkbox-ов или форма согласия изменились, остановись с
`court_consent_changed`: новое либо дополнительное согласие не угадывай.

Пользователь участвует только в настоящем ручном шаге: Touch ID/пароль ОС при
защищённом обращении к Госуслугам, CAPTCHA, SMS/push/OTP, recovery, неожиданный
выбор личности/роли, фактическая подпись в Госключе либо новое нестандартное
согласие. Перед необратимой подачей остановись, если текущая просьба не разрешает
точные суд, обращение, текст и комплект файлов.

## Запуск и браузерная сессия

Один раз перед первым внешним действием получи текущий `get_agent_skill` для
ГАС и выполняй exact `runtimeExecution.localAction`. Legacy command допустим
только по правилам host. Не запускай исходники, Computer Use, другой browser
tool или прямой HTTP вместо runtime.

1. `doctor` проверяет host browser runtime, encrypted snapshot и native boundary без системного prompt. При `runtimeReady=false` один раз выполни `bootstrap`. Ошибка login Keychain означает проблему доступа к хранилищу, а не необходимость Touch ID или потерю ЕСИА-сессии; не пересоздавай key автоматически.
2. `start` открывает headed Chrome/Edge в фоне и возвращает `sessionId`/`expiresAt`. Активная exact сессия переиспользуется: не создавай второе окно и не продлевай срок повторным `start`.
3. При `phase=ready` используй `snapshot`, `page` либо предпочтительный полный `script`. `script --session ID --input-file ABSOLUTE_SCRIPT` принимает owner-only JavaScript-файл вне Git/Workspace. Код – тело async-функции с готовыми `context`, `page`, `console`; доступны обычные Playwright API, popup, iframe, upload/download и нужные переходы. Удали временный файл после вызова.
4. Каждый следующий вызов получает тот же context. Не закрывай browser/context между анализом, заполнением формы и возвратом ЕСИА. Не возвращай из сценария cookies, storageState, auth поля, URL с code/state или целые browser/network objects. `ok:true` подтверждает выполнение кода, но не юридический результат на сайте.
5. После действия проверь свежую страницу в той же сессии. После timeout, `script_result_unknown` или потери ответа сначала прочитай фактическое состояние; отправку, подписание или удаление вслепую не повторяй.
6. После результата либо отмены выполни `stop --session ID` и проверь `phase=closed`. Logout и удаление сохранённой сессии не нужны. `forget --confirm` – отдельное явно запрошенное удаление локального key/ciphertext, не logout у ГАС или ЕСИА.

Браузер не headless, но обычная работа, восстановление snapshot, status и
действия не активируют окно и не забирают фокус. `show --session ID` или
`page.bringToFront()` допустимы только когда человеку действительно нужен
ручной шаг либо он прямо попросил показать окно. После ручного шага продолжай
в той же вкладке.

## Вход через Госуслуги

Вход выполняется внутри уже открытой сессии ГАС, а Госуслуги отвечают только за
ЕСИА и свои сохранённые credentials.

1. Получи текущий назначенный навык Госуслуг в том же company/project context и вызови его verified `client`. Сохрани bounded nonsecret ответ в owner-only JSON вне Git/Workspace.
2. Для поручения, требующего кабинет, вызови `prepare-sign-in --session GAS_ID --input-file CLIENT_JSON --confirm [--request-title TOPIC]`. `--confirm` здесь отмечает уже данное поручением право войти – отдельного вопроса пользователю не нужно. Госуслуги сами читают точное название чата в Codex; TOPIC – необязательная короткая тема на случай недоступного чтения или работы в Claude Code, не текст страницы.
3. Runtime сам открывает форму входа ГАС в фоне, проверяет точную известную форму соглашения, отмечает стандартный checkbox, создаёт helper ЕСИА до клика и нажимает штатную кнопку «Войти». Он возвращает только безопасные opaque IDs и `arguments`.
4. Передай `arguments` exact verified `authorize` runtime Госуслуг автоматически, без отдельного напоминания пользователя о способе входа. Если обычная сессия Госуслуг уже `ready`, runtime принимает transaction в ней, не запрашивает повторный Touch ID/пароль ОС и не закрывает её текущую страницу. Системная разблокировка возможна только при создании новой защищённой сессии; окно ЕСИА показывается только для CAPTCHA, SMS/push/OTP либо другого обязательного ручного шага. Не делай snapshot/auth DOM ЕСИА и не вводи секреты через ГАС-сценарий.
5. После успешного `authorize` вызови `resume --session GAS_ID`. При `authorization_pending` человек заканчивает текущую проверку в уже открытом окне, затем повторяется `resume`; не создавай новый helper и не нажимай вход повторно. `phase=ready` означает проверенный callback в исходный context, после чего свежей страницей отдельно докажи готовность кабинета.

При `authorization_failed` попытка завершена и helper удалён; ответ и `status`
сохраняют безопасный код причины. Не вызывай прежний `authorize`/`resume` и не
начинай вход повторно автоматически. Проверь фактический результат и границы
поручения; если новая попытка разрешена, отдельный `prepare-sign-in --confirm`
в той же сессии вернёт исходную вкладку на публичный ГАС и создаст новый helper.
Перед ним используй текущий verified `client` Госуслуг. Браузер, context и
исходный deadline сохраняются; auth DOM в этом состоянии не снимай.

Сессионный snapshot ГАС содержит только cookies/origin storage `sudrf.ru` и
зашифрован AES-256-GCM ключом текущей учётной записи ОС. ЕСИА-state в него не
попадает. ГАС – нефинансовый контур: `start`/reuse не требуют Touch ID или
CredUI. Делегированный runtime Госуслуг сохраняет собственную более строгую
границу и 30-минутный deadline.

## Проверка статуса

1. Ищи по точному регистрационному номеру, а не по позиции или похожему названию.
2. Запиши время проверки и источник. Не считай старую сохранённую страницу свежим ответом.
3. Статус обращения в кабинете и публичная карточка дела могут расходиться; проверяй их отдельно, если нужны оба факта.
4. Не выводи процедурный итог из одного статуса `Зарегистрировано`. Если история недоступна, так и скажи.
5. Проверка статуса не разрешает создавать черновик, загружать документы или отправлять обращение.

## Подготовка файлов для любой судебной подачи

Применяй этот порядок к новому обращению, документам в существующее дело и
копиям для участников дела. Выполни проверку до подписания, загрузки и финальной
отправки; повторная подача после отклонения требует такой же проверки.

1. Прочитай состав комплекта и содержимое каждого окончательного PDF. Каждый
   самостоятельный документ представь отдельным файлом: не объединяй иск,
   ходатайство и самостоятельные приложения в один PDF. Страницы одного
   многостраничного документа сохраняй вместе; требование отдельных файлов
   не означает отдельный файл для каждой страницы.
2. Для внешних судебных файлов используй человекочитаемую транслитерацию
   русских названий, а не английские описания (`response`, `demand`, `followup`,
   `dispatch-report`). Название должно определять вид и предмет документа;
   добавь дату или номер, если они нужны для различения. Не добавляй технические
   маркеры `signed`, `final`, `draft`, `facsimile`, если они не входят в
   официальное название. Транслит — рабочее правило навыка, а не отдельное
   требование суда использовать латиницу.
3. Проверь фактическое количество страниц окончательного PDF локальным
   PDF-парсером и укажи количество листов в имени как `-Nl.pdf`, где N —
   проверенное число. Например, для документов соответственно на 3 и 1 лист:
   `iskovoe-zayavlenie-2026-10-01-3l.pdf` и
   `hodataistvo-ob-istrebovanii-dokazatelstv-1l.pdf`. Не бери число из черновика,
   списка приложений, имени исходника или примера. Если содержимое либо число
   страниц не проверено, комплект не готов: останови загрузку и подачу,
   обозначь конкретный недостающий источник или инструмент.
4. Составь полный перечень подачи: русское название документа, окончательное
   имя файла, проверенное количество листов, SHA-256 PDF и соответствующая
   отдельная подпись `.sig`, когда она требуется. До подписи заверши разделение
   документов, правки PDF и выбор названий. Любое изменение байтов PDF, включая
   разделение или объединение, требует новой подписи изменённого документа;
   прежнюю подпись используй только при точном совпадении SHA-256. Простое
   переименование копии не меняет байты, но пару PDF/`.sig` всё равно сопоставь
   по проверенному документу. Исходные файлы пользователя не изменяй.
5. После загрузки и на итоговом экране сверь каждый файл с перечнем, включая
   имя, количество листов и подпись. Если ГАС предлагает отдельное видимое
   наименование документа, укажи понятное русское название с количеством листов;
   имя на диске не доказывает правильного названия в форме. Удали дубли и старые
   файлы черновика только в рамках разрешённого редактирования. Без этой
   сверки комплект не готов к отправке.

## Подача документов в существующее дело

1. Уточни точный суд, номер дела, вид производства, процессуальный статус и адрес для извещений.
2. Для смешанного комплекта письменной позиции, заявлений, ходатайств и приложений используй подходящий тип формы; не полагайся на визуально выбранное значение, пока оно не сохранено.
3. Проверь заявителя и каждого участника. Не угадывай организацию либо роль по похожему названию.
4. Выполни раздел «Подготовка файлов для любой судебной подачи». Основной документ загрузи в предназначенный для сути обращения раздел, остальные файлы – как приложения.
5. Для каждого PDF приложи matching detached signature и проверь видимый признак УКЭП. Обычный OpenSSL не является достаточной проверкой ГОСТ/CMS `.sig`; по умолчанию сверяй источник, имя, число файлов, ненулевой размер и checksum, а криптографическую проверку делай только ГОСТ-совместимым валидатором.
6. На итоговом экране повторно сверь суд, дело, стороны, текст, файлы и подписи. Если номер дела не показан, вернись в редактирование и проверь сохранённое поле.
7. Финальное `Отправить` выполняй только в рамках прямого поручения на эту точную подачу. После неоднозначного ответа сначала проверь историю; не повторяй отправку вслепую.

Стандартную публичную форму входа с HTTP 401 runtime распознаёт по полному
известному соглашению и продолжает вход. Это не подтверждает вход в кабинет;
401 другого документа либо callback остаётся ошибкой.

При `service_http_error` используй `httpStatus` и `httpOrigin`: `503` означает,
что сервис на этом origin недоступен. Не называй это неверным паролем или багом
авторизации и не утверждай технические работы без отдельного подтверждения.
Не запускай setup/forget и новый вход автоматически; после неизвестной отправки
сначала проверь её фактический результат. Auth DOM и OAuth URL ради диагностики
не снимай. Если старый ответ не содержит HTTP-кода, не угадывай его.

HTTP-ошибка рабочего документа не закрывает сессию. Чтобы уйти с 404 на другую
официальную страницу, используй `page --session ID --navigate URL` (либо private
JSON `action=navigate`). Для read-only URL snapshot ошибочной страницы не нужен;
затем продолжай обычный `script`/`snapshot`. Полный `script` до этого остаётся
закрыт, поскольку получает доступ к текущему ошибочному документу. Writable route,
активная ЕСИА и auth-страница не получают исключения. После перехода новая
HTTP-ошибка возвращается отдельно; новый login, browser и повтор отправки не нужны.

## Совместимость

Runtime поддерживает macOS с Chrome и Windows 10/11 x64 с Edge; нужен Node.js
>=22. `start --channel chrome|msedge` выбирает установленный браузер. Linux и
cloud-only завершаются fail-closed. Одна сессия живёт максимум 30 минут от
`start`; команды и сон не продлевают срок. Native guardian закрывает owned
browser/worker при expiry, crash или hang. Подробности –
[контракт runtime](references/secure-runtime.md).

После pending выполняй `continuation.arguments` того же localAction: wait
наблюдает результат без сообщения «заполнил». Правила – в references.
