# Trelio Agent Skills

Публичный репозиторий общих provider Agent Skills Trelio.
Инструкции, runtime-код, тесты и инструменты сборки публикуются отдельно от
корпоративных навыков, личных подключений и production signing.

В `platform-skills/` находятся 25 общих навыков: 1С ЭДО, Авито, ВКонтакте, КонсультантПлюс,
DeepSeek Search, DodoStats / DrinkitStats, Google: поиск и ИИ, GigaChat, почта, ГАС «Правосудие», Госуслуги,
iPhone Mirroring, Perplexity Search, Yandex Search, ИИ-Консьерж от Гига / Сбер,
MAX, поиск Ozon, заказные письма Почты России, Т-Банк, Telegram MTProto,
Telegram Web, WhatsApp, факсимиле для документов, ВК Реклама и локальная расшифровка аудио. Для конкретного provider
читай его `SKILL.md`.

[ИИ-Консьерж от Гига / Сбер](platform-skills/giga-concierge/SKILL.md) —
instruction-only навык для поручений официальному боту: звонки, бронирование,
подбор поездок и напоминания. Требует хотя бы одного доступного подключённого
навыка Telegram MTProto, Telegram Web или MAX. Сам не устанавливает зависимость,
не хранит сессию и не запускает фонового исполнителя. Публично заявленные
возможности проверяются в конкретном аккаунте; source не означает публикацию
или назначение в live каталоге Trelio.

Локальная расшифровка использует официальную GigaAM `v3_rnnt` на CPU.
При первом разрешённом использовании навык сам загружает закреплённую модель
и отдельную Python-среду без вопроса владельцу; аудио остаётся на устройстве. Длинные записи обрабатываются потоком с
прогрессом, отменой и продолжением, результат – исходные TXT/SRT/JSON.
Восстановление пунктуации не обязательно и выполняется агентом лишь по просьбе
пользователя, в отдельной копии без изменения слов. Поддерживаемые
targets: macOS Apple Silicon, Windows x64, Linux x64 (glibc).
Инварианты установки, приватного хранения и восстановления –
[в контракте навыка](platform-skills/audio-transcription/references/workflow.md).
Для прежних точных весов есть резервное HTTPS-зеркало Trelio с полным size/SHA
контролем; TLS и integrity не ослабляются, аудио на зеркало не отправляется.

Авито – прототип браузерного навыка: модель получает отрисованный текст и
координаты, PNG по запросу; голосовые и входящие вложения выдаются локальными originals,
исходящие выбираются через штатную кнопку вложения с сохранением имён и bytes.
Допустимость формата определяет Авито; до первого ответа собеседника доступны
только текстовые сообщения. Ручной вход сохраняется локально в защищённой сессии.
Документы требуют отдельной кнопки «Отправить файл»; её доступность зависит
от подтверждения профиля и категории. Фото/видео не заменяют этот способ.
Нужен host visual API >=3.28.3; source и PR не
означают публичную готовность до native CI и signed host/provider release.

ВКонтакте использует визуальный host API >=3.17.0: поиск, страницы,
сообщества и диалоги по отрисованному тексту и PNG, обязательный вход через VK ID,
защищённый локальный snapshot и отдельный личный account. Разделы VK доступны
по задаче пользователя; scope охватывает HTTPS vk.ru/vk.com с поддоменами и vk.me.
Исходящие originals любых форматов выбираются через штатную кнопку вложения,
по одному или несколько; сохраняются исходные имена и байты. Допустимость
конкретного типа определяет VK. Доступность действия определяется его интерфейсом.
ВК Реклама предоставляет отдельный рекламный API. Входящие originals ограничены signed origin policy;
редирект на внешний CDN может быть недоступен. Source и синтетические тесты не
доказывают текущую совместимость живого VK: до signed release нужен live smoke.

[Google: поиск и ИИ](platform-skills/google-ai-search/SKILL.md) (`google-ai-search`)
объединяет обычную выдачу Google и AI Mode на `g.ai` в собственных скрытых вкладках.
Агент выбирает режим по задаче, сохраняет явный выбор пользователя и уточняет
вопросы в той же AI-беседе. Обычные запросы содержат тему и ограничения целиком;
органические ссылки, реклама и ИИ-обзоры различаются, первоисточники проверяются.
Общий минимальный интервал 2–15 секунд учитывает размышления и чтение источников,
ожидается только остаток. Это instruction-only навык без API/runtime; скрытая
вкладка не обещает headless process. Source не означает публикацию или назначение
в live каталоге Trelio. [Браузерная проверка](platform-skills/google-ai-search/development/browser-smoke.md).

GigaChat (`gigachat`) работает через скрытую вкладку `giga.chat`: вопросы,
уточнения в одной беседе, доступные режимы «Гига», «Исследование» и «Рассуждение»,
чтение ссылок и проверка первоисточников. Публичный текстовый диалог может
работать без входа; требование авторизации определяется живым интерфейсом.
Это instruction-only прототип без API/runtime, отдельный от `giga-concierge`.
Наличие исходника не означает публикацию или назначение в каталоге Trelio.

[Perplexity Search](platform-skills/perplexity-search/SKILL.md) использует тот же
instruction-only подход: скрытая вкладка сайта, ответ и уточнения в одной
беседе, без API-ключа. Источники сопоставляются с отдельным вопросом: общая
панель может объединять несколько ходов. Controller выдерживает минимальный
интервал 2–15 секунд с зачётом размышлений и чтения источников. Реальный цикл
с двумя ответами и открытием первоисточников проверен в
[браузерном smoke](platform-skills/perplexity-search/development/browser-smoke.md).
Source не означает публикацию или назначение в live каталоге Trelio.

[DeepSeek Search](platform-skills/deepseek-search/SKILL.md) работает через
скрытую вкладку `chat.deepseek.com` без API: «Умный поиск», уточнения в той же
беседе и «Глубокое мышление» для анализа и сравнения. Вход определяется живым
интерфейсом и выполняется пользователем. Оба режима проверены вместе;
мышление не гарантирует точные цитаты, поэтому проверяются href и содержание
первоисточников. Полный цикл описан в
[браузерном smoke](platform-skills/deepseek-search/development/browser-smoke.md).
Source не означает публикацию или назначение в live каталоге Trelio.

Яндекс (`yandex-search`) объединяет обычную выдачу `yandex.ru/search/` и чат
`alice.yandex.ru` в скрытых вкладках. Агент сам выбирает поиск или обсуждение,
уточняет свои вопросы и отвечает на встречные вопросы Алисы в той же беседе.
Явный выбор пользователя сохраняется; мнение Алисы отделяется от проверки фактов.
Общий интервал 2–15 секунд учитывает размышления и чтение источников,
перед следующей отправкой ожидается только остаток.

Текущую доступность подписанного навыка ВК Реклама определяет live каталог
Trelio, а не наличие исходников. Для новых функций чтения нужен безопасный
GET smoke; новые записи проверяются только на отдельно разрешённых тестовых
объектах без запуска показов.
Метаданные счётчика в сегменте сопоставляются по публичному params.source_id,
а не внутреннему объекту связи. Неполная выборка и неоднозначность не скрываются;
поля частоты и границы трактовки условий описаны в diagnostic reference.
OAuth auth recovery отдельно требует решения на отзыв всех grants пользователя;
один revoke/одна новая пара защищены scoped планом и persistent unknown-fence.
Это восстановление подключения, а не рекламная запись или точечный отзыв токена.
`sources --type search-phrases --id ID` читает сами поисковые и минус-фразы;
название сегмента не заменяет источник правил, единица периода и expansion
сохраняются как неизвестные, если официальный API их не определяет.
Управление сегментами/источниками, rename/delete загруженных списков и явная
Top goal привязка используют scoped plan/apply из
[контракта управления](platform-skills/vk-ads/references/audience-management.md).
Новые write-пути проходят синтетические тесты; реальный результат конкретного
кабинета устанавливает его отдельно разрешённая операция с read-back.
Источник подписчиков VK-сообщества отдельно разрешается в рекламном словаре,
регистрируется и читается с состоянием загрузки. Публичный ID и внутренний ID
источника не смешиваются; legacy official contract не доказывает доступность
нового endpoint в конкретном кабинете ads.vk.com.

Корпоративные 1С и устаревший Telegram-пилот сюда не входят. История начинается
с отобранного source snapshot; исторические release tags сохраняют первоначальную
provenance. Текущие опубликованные версии и подключения Trelio не меняются от
переноса исходников. Новый tag не создаётся только ради изменения repository.

`platform-skills/tools/` содержит детерминированный builder и регрессии.
Проверки идут на Linux/macOS/Windows через GitHub Actions. Быстрый локальный gate:

```sh
node --test platform-skills/tools/*.test.mjs
node platform-skills/tools/check-public-source.mjs
```

[Порядок выпуска](docs/release-process.md) сохраняет production signing на
backend. Telegram CI сохраняет credential-free `.skilltmpl`; backend добавляет
application identity перед подписью final package. Полные provider tests
выполняются только здесь, сервер отдельно проверяет materialization/signing. Корпоративные source и старые artifacts сохраняются
приватными. Лицензии сторонних компонентов лежат рядом с их исходниками;
отдельная новая лицензия на весь проект этим переносом не вводится.

## Метаданные каталога

В `SKILL.md` технический `description` описывает выбор навыка агентом.
Короткие человекочитаемые название и описание Trelio хранятся отдельно в том же
frontmatter:

```yaml
metadata:
  catalog_title: "Название навыка"
  catalog_description: "Краткое русское описание для карточки"
```

Publisher читает только эту explicit пару при exact совпадении `name` с ID
навыка (для company-private — с catalog slug). H1 и технический `description`
не являются fallback: старые исходники без пары сохраняют текущую карточку.
Canonical reader/projection — public `platform-skills/tools/skill-source-metadata.mjs`.
Browser/backend/host/private tools получают generated exact copy; отдельной YAML
реализации нет. Display-only пара исключается до byte guard/encryption и не
повторяется в model instructions; technical description/body остаются прежними.
Изменения переносятся вместе с новой публикацией и проверяются read-back;
редактирование source не переписывает текущую карточку или immutable tags.


Публичные требования подключения принадлежат каждому навыку в отдельном
`platform-skills/<id>/catalog-requirements.json`:

```json
{
  "schemaVersion": 1,
  "companySetup": false,
  "personalAccount": "required",
  "authorization": "browser",
  "connectionLabel": "Личный аккаунт сервиса"
}
```

Ровно пять полей: `companySetup` — boolean, `personalAccount` — `required`,
`optional`, `not_required`; `authorization` — `browser`, `token`, `null`;
`connectionLabel` — непустой однострочный текст до 240 символов. Это сведения
для человека, не настройки/credentials/состояние аккаунта и не runtime authority.
Не добавляй company content, пути, endpoint или новые поля без изменения контракта.
Проверяй условия по полному workflow и входу навыка; local session сама по себе
не доказывает обязательность аккаунта. Общий validator —
`platform-skills/tools/catalog-requirements.mjs`; Trelio получает generated copy.

JSON не включается в SKILL.md, model instructions или executable package.
Publisher читает его из того же exact source commit и связывает с reviewed
catalog metadata plan. Старый tag без файла сохраняет live requirements;
невалидный файл блокирует публикацию. Для metadata-only правки после merge
используется `ops/scripts/sync_agent_skill_catalog_requirements.mjs` репозитория
Trelio: clean merged public source → source SHA/live catalog CAS plan → exact
hash apply → read-back. Текущие live title/description сохраняются. Version/tag
навыка, runtime и продуктовый релиз для такой правки не создаются; одна правка
source сама по себе ещё не изменяет live каталог.
