# Отправка почты и безопасная диагностика

`email-imap-smtp` передаёт письмо один раз через SMTP и отдельно сохраняет
принятые MIME-байты в `\Sent`. Наличие подключения, положительный `NOOP` и
пустая папка отправленных не доказывают результат передачи конкретного письма.
Настройки и личные правила ящика не меняются при сбое отправки.

## Вложения

Для `.eml` и определённых системой контейнерных MIME-типов `message/*` и
`multipart/*` используется `application/octet-stream` с исходным filename и
base64 точных байтов файла. Парсинг и повторная сериализация оригинала запрещены:
они могут изменить заголовки, переносы строк, подписи и вложенную структуру.
Другие файлы сохраняют определённый MIME-тип и точные байты.

Причина: RFC 2046 §5.2.1 запрещает base64 непосредственно на `message/rfc822`;
§5.1 запрещает его на `multipart/*`. Передача источника как обычного файла
сохраняет оригинал без такой некорректной структуры. ZIP не создаётся автоматически.

Внешнее письмо сериализуется один раз с CRLF и 7-bit кодированием тела;
международные адреса требуют SMTPUTF8. В SMTP DATA и IMAP APPEND идут одинаковые
байты, Bcc в заголовок не попадает.

## Результат и ошибки

Совместимые поля `ok`, `error`, `sent`, `smtpStatus`, `sentCopy`, `messageId`
сохраняются. SMTP-ошибка имеет дополнительный объект `smtp` в stdout/stderr
нативного worker и direct CLI. Оба пути используют `error_payload`.

| Поле | Смысл |
| --- | --- |
| `stage` | connection, tls, authentication, preflight, send, mail_from, rcpt_to или data |
| `outcome` | rejected: явный отрицательный SMTP-ответ; not_attempted: ошибка до sendmail; unknown: приём после начала sendmail не установлен |
| `smtpCode` | Проверенное целое 400–599 или null; при разных RCPT-ответах общего кода нет |
| `enhancedStatusCode` | Начальный 4.x.x/5.x.x с классом, совпадающим с SMTP-кодом, или null |
| `reasonCode` | Фиксированная безопасная категория; классификация ответа, не дословный текст или доказанная первопричина |
| `reasonSource` | safe_response_classification либо exception_category |
| `responseTextOmitted` | Всегда true: raw reply не возвращается и не сохраняется |
| `temporary` | true для 4xx, false для 5xx, null без общего кода |
| `automaticRetryAllowed` | Всегда false; категория ошибки не расширяет разрешение отправки |
| `messageId` | Идентификатор текущей попытки, добавляется ошибкой send |
| `wireBytes` | Размер сериализованного письма или null, если оно ещё не сериализовано |
| `attachmentCount` | Число исходных файлов текущей попытки |

Проекция читает максимум 1024 байта ответа для кодов и фиксированных категорий
spam, malware, size, quota, rate и format. Неизвестная причина остаётся общей
категорией. В модель и логи не копируются raw response, traceback, адреса из
ответа, URL, identifiers, credentials, тема, тело или содержимое вложений.

При полном RCPT-отказе `smtp.recipientResponses` содержит число отказов и
до 20 безопасных ответов без адресов. При частичном приёме такое же поле
возвращается рядом с существующим `refusedRecipients`; SMTP-приём остальных
адресатов и сохранение копии не отменяются. `truncated` явно обозначает лимит.

Первоначальная ошибка передачи фиксируется до QUIT. Последующая ошибка закрытия
не заменяет DATA/RCPT-отказ; после подтверждённого приёма она остаётся отдельным
`smtpCleanupWarning`, а копия сохраняется обычным порядком. Ошибка отправки
никогда не создаёт ложную копию в Sent и не вызывает повтор.

`doctor.smtpChecks` перечисляет connection/authentication/noop;
`messageAcceptanceChecked=false` прямо ограничивает вывод об исправности.
Проверять доставку через повторную отправку без соответствующих полномочий нельзя.

## Проверки

`test_send_diagnostics.py` проверяет точные байты EML/PDF, реальный stdlib
SMTP DATA parser на синтетическом transcript, 4xx/5xx, transport ambiguity,
QUIT masking, SMTPUTF8 preflight, partial acceptance, bounds/redaction и
структурированный CLI-result. `test_sent_copy.py` сохраняет независимые
SMTP/Sent-copy инварианты; обязательный native CI выполняется на macOS/Windows.
