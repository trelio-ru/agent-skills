# Браузерный резерв почтового навыка

Обычный почтовый ящик может иметь второй способ работы. Выбор аккаунта делает
host по `local-accounts-v1`, а защищённая локальная форма собирает начальный
HTTPS-адрес веб-почты и дополнительные exact origins авторизации. Каталог
провайдеров не требуется. SMTP-only даёт отправку через relay и не получает
доступ к другому почтовому ящику.

Для точных публичных адресов [Gmail](https://support.google.com/mail/answer/8494),
[Яндекс Почты](https://yandex.ru/support/yandex-360/customers/mail/ru/auth.html)
и [Почты Mail](https://help.mail.ru/mail/login/qr/) навык добавляет основной
origin входа и origin родительского cookie. Дополнительные корпоративные,
региональные и сторонние SSO origins задаёт владелец.

## Сессия и cookies

Python entrypoint для `webmail` запускает подписанный sibling adapter через
Node из того же host. Собственный native IMAP/SMTP worker, Keychain/DPAPI
и password transport не участвуют. Common Visual Browser использует
`protected-snapshot` на exact selected account, а live worker дополнительно
проверяет owner, компанию, runtime session и исходную lease. Адреса владелец
вводит в общей защищённой форме. Маршрут хранится локально под тем же
account lock, отдельно от паролей и cookies.

Обычный профиль Chromium сохраняет поддерживаемые host auth stores, в том
числе cookies, localStorage, IndexedDB, WebStorage и session-only cookies.
Дополнительные HTTPS origins позволяют сохранять связанные SSO cookies.
Для cookie родительского домена укажи exact HTTPS origin этого домена.
Значения cookies, браузерные секреты и содержимое формы остаются вне MCP,
argv и логов. Snapshot и ключ хранятся прежним защищённым способом host.

Владелец может добавить origins к существующему маршруту после завершения
его окна. Один snapshot сохраняется для того же ящика и начального origin.
Прямой перенос браузерной сессии между аккаунтами или на другой origin
потребовал бы отдельного нового подключения и не выполняется здесь.

## Маршрутизация

Инструкция предлагает подключить резерв при обычной первой настройке и
при отказе IMAP/SMTP, если у того же ящика нет рабочего резерва. Начало формы
и snapshot не подтверждают готовность конкретного сайта. Primary read,
отправка, UID/ACK и фоновые assistant-команды остаются в прежних transports.

`webmail open` передаёт человеку принадлежащее навыку видимое окно. Для
автоматического наблюдения владелец может задать exact подпись видимого
элемента аккаунта, включающую адрес ящика. Adapter сверяет один положительный
контрол того же snapshot до выдачи текста. При отсутствии нужного признака
остаётся ручное управление. Следование ссылке использует свежий однозначный
control того же окна, адрес из интерфейса и тот же начальный HTTPS origin.

В первую версию входят открытие и возобновление сессии, автоматическое
наблюдение доступного текста и переходы по ссылкам интерфейса. Составление
и отправка в веб-почте выполняются человеком. Браузерный путь не повторяет
неизвестную SMTP-отправку; проверка «Отправленных» остаётся отдельным чтением.
